ARCHITECTURE EXPLANATION
================================================================================

Why two files? THIS IS INDUSTRY STANDARD.

┌─────────────────────────┐
│ Your FPGA Design        │
│ (Efinix T120)           │
└────────────┬────────────┘
             │
     ┌───────▼──────────────────────┐
     │ mdio_master_top.sv           │  ← Efinix-specific wrapper
     │ (GPIO tri-state handling)    │     Only needed for this FPGA
     └───────┬──────────────────────┘
             │
     ┌───────▼──────────────────────┐
     │ mdio_master.sv               │  ← Core MDIO protocol logic
     │ (100% reusable)              │     Works on ANY FPGA
     │ - APB interface              │
     │ - Clock divider              │
     │ - Clause-22 protocol         │
     └───────┬──────────────────────┘
             │
     ┌───────▼──────────────────────┐
     │ tb_mdio_master.sv            │  ← For testing only
     │ (Testbench - tests core)     │     Simulation-only
     └──────────────────────────────┘

Benefits:
  ✅ Core logic is portable (reuse on Xilinx, Altera, etc.)
  ✅ Easy to test independently
  ✅ Follows industry patterns (Xilinx, ARM, Altera all do this)
  ✅ Minimal wrapper (~76 lines) for platform-specific code
  ✅ Separate concerns: protocol vs. hardware
