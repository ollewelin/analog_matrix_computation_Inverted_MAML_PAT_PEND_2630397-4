# T120 <-> T20 Inter-FPGA Bridge: Two-Bus Specification

Status: **T120 side implemented** (`FPGA_code/T120F324/t120_inter_fpga_bridge.sv` and sub-modules). T20 side is the next task and must follow this document.

---

## 1. Design Requirements (priority order)

1. **R1 — Hadamard is 100 % hardware-synchronous (VERY IMPORTANT).**
   The Hadamard excitation must be synchronous from T120 to T20 all the way into the analog matrix. Any timing jitter at the matrix inputs becomes a signal-integrity problem in the analog result.
   * **No processor (C code) may ever be in the Hadamard timing path**, on either FPGA.
   * No CRC, no framing handshake, no retry and no back-pressure on the Hadamard path. The bus is short and on-board; bit errors are not expected. Timing is the essence, not bit correction.
   * Only a **1-bit ACK** returns, as a timing proof/monitor. It never stalls or alters the stream.
2. **R2 — Service traffic may be software driven.** T20 SoC debugging/trace, SPI-flash update, JUMP, configuration and table loading go through C code over a separate bus, and are allowed to be slow and jittery.
3. **R3 — Light weight.** The T20 is the smaller device and also hosts a minimal Sapphire SoC. Both buses must be implementable on T20 with a few shift registers, one small FSM and one CRC8 LFSR.
4. **R4 — One clock.** Both buses are synchronous to the single bus clock `T20_CLK9`, generated by the T120. T20 uses `T20_CLK9` as the clock of its bus/Hadamard logic.

Because the wires are free to be assigned (pure single-ended GPIO, directions fixed by each FPGA's peripheral config), the physical wires are split into two **independent** buses.

### 2.1 Clocking and edge rules (apply to both buses)

* T120 generates `CLK9` from `sys_clk` (50 MHz) with an integer period `N` sys cycles (`N=5` -> 10 MHz, `N=40` -> 1.25 MHz, default `N=25` -> 2 MHz). Everything on T120 stays in the `sys_clk` domain: bridge launch/sample instants are derived from the same counter as `CLK9`, so there is **zero relative jitter** between `CLK9` and the data lanes.
* **T120 launches all TX lanes on the falling edge of CLK9.** T20 samples them on the following **rising** edge (half-period setup/hold margin: 50 ns at 10 MHz).
* **T20 launches all RX lanes (`H_ACK`, `S_RX`) on the rising edge of CLK9** (registered outputs, no combinational paths). T120 samples them through a 2-flop synchroniser on the CLK9 rising event; optional extra sample delay `rx_dly` 0..7 sys cycles for bring-up.
* On T20, `CLK9` must enter on a clock-capable pin and be used as a real clock (global buffer), not sampled as data.

## 3. H-bus: Hadamard Synchronous Bus (hardware only)

### 3.1 Principle
The CPU only prepares data and starts a run. The hardware sequencer then emits one Hadamard word every `H_PERIOD` CLK9 cycles, exactly periodic, until `H_COUNT` words are done (or loops). T20 receives the bits with a plain shift register clocked by `CLK9` and applies the vector at a fixed CLK9 edge. No processor touches either side after `START`.

### 3.2 Word format (width `W`)
`W` is a synthesis parameter (`H_WIDTH`, default 16, max 32), identical on T120 and T20 (FWHT 16/32 butterfly width).

* A word is `W` consecutive CLK9 cycles on `H_DATA`, **MSB first**.
* `H_SYNC` is high for exactly one cycle, together with the MSB (bit `W-1`). Between words `H_DATA` and `H_SYNC` are 0.
* `H_PERIOD >= W + 3` CLK9 cycles (hardware clamps lower values).
* T20 **restarts its capture on every `H_SYNC`**, so a stopped/partial word never desynchronises it.

Timeline, with `F(n)` = n-th CLK9 falling edge (T120 launch) and `R(n)` = the rising edge that follows it (T20 sample):

| Event | Time |
|:---|:---|
| `H_SYNC` + bit `W-1` launched | `F(S)` |
| bit `W-1-j` launched | `F(S+j)`, `j = 0..W-1` |
| T20 samples last bit (LSB) and loads its vector register | `R(S+W-1)` |
| **Vector valid at T20 outputs (apply instant)** | just after `R(S+W-1)`, i.e. `W - 0.5` CLK9 cycles after `F(S)` |
| T20 launches `H_ACK` (1 cycle pulse) | `R(S+W)` |
| T120 detects `H_ACK` | measured latency **`W + 3` CLK9 cycles** from the sync cycle (verified in simulation at 10 MHz and 2 MHz; the value read from `H_LAT_*` on hardware must be constant, `rx_dly` can shift the sample point if board delays move it by one) |

The apply instant is a **constant offset** from `H_SYNC`, independent of period, table content and software. The T120 can therefore schedule anything else (ADC, S/H timing) relative to `h_step_strobe` with fixed cycle offsets.

### 3.3 ACK (1 bit, timing proof only)
* T20 pulses `H_ACK` for exactly one CLK9 cycle, launched on `R(S+W)`, once per word.
* T120 measures the latency (CLK9 cycles from the SYNC cycle to the first ACK of that word) and stores `last/min/max`. **`H_LAT_MIN == H_LAT_MAX` proves zero jitter.**
* An ACK outside `[H_ACK_WIN.min, H_ACK_WIN.max]` or no ACK before `max` increments `H_ACK_MISS` and sets the sticky flag. This is a monitor only: the stream is never paused, repeated or altered. `ack_en=0` disables the check.
* No CRC and no parity on the H-bus.

### 3.4 T120 hardware (`t120_hbus_seq.sv`)
* Table: 256 words x 32 bit BRAM (low `W` bits used), written by the CPU before the run through the APB window `0xC00..0xFFF`.
* `START` is latched and takes effect at the next CLK9 falling edge (start phase uncertainty is at most one CLK9 period; **inter-word timing after the start is exact**). Optionally `loop`.
* Outputs `h_step_strobe` (one `sys_clk` pulse per word, aligned to the SYNC cycle) and `h_active` for other T120 hardware that must stay in lock-step.

### 3.5 T20 hardware requirements (to implement next)
* `W`-bit shift register on `CLK9`, `SYNC` restarts a bit counter, vector register loaded at the last bit, `ack` flop launched one cycle later. No SoC, no FIFO, no CRC in this path.
* The vector register drives the Hadamard/matrix control logic directly in the same `CLK9` clock domain (or a clock derived with a fixed phase relation from it). Any crossing to another clock must be a fixed-latency design reviewed for jitter; **never** through the processor.

## 4. S-bus: Service Bus (software driven, light, CRC8)

Strictly **request/response, T120 is master**; T20 never transmits unsolicited (trace is polled). Software only: SoC bring-up/debug, SPI flash bitstream update, JUMP, Hadamard configuration/status, random table load.

### 4.1 Channels

| Channel | Use |
|:---|:---|
| `0x01` | Remote SPI-flash bitstream update (WRITE chunk, VERIFY, JUMP via `CONFIG_CTRL0`) |
| `0x02` | Hadamard **configuration / status** (W, enable, T20 monitor read-back). **Never carries Hadamard timing data** (that is the H-bus) |
| `0x03` | Random table / vector load into T20 memory |
| `0x04` | Bidirectional trace / debug (T120 polls, T20 returns trace bytes) |

### 4.2 Frames
CRC8: polynomial `0x07`, init `0x00`, MSB first, computed over **every byte after the `0xA5` preamble**.

T120 -> T20, 2 bits per CLK9 cycle (4 symbols per byte, MS pair first, idle symbol `00`):

| Field | Bytes | Description |
|:---|:---|:---|
| `PREAMBLE` | 1 | `0xA5` |
| `CHANNEL` | 1 | see 4.1 |
| `SEQ/OP` | 1 | opcode / sequence |
| `LENGTH` | 2 | payload bytes, big endian, `0..1024` |
| `PAYLOAD` | N | |
| `CRC8` | 1 | |

T20 -> T120, 4 bits per CLK9 cycle (high nibble of every byte first, idle nibble `0x0`):

| Field | Bytes | Description |
|:---|:---|:---|
| `PREAMBLE` | 1 | `0xA5` (nibbles `A`,`5`) |
| `RESP` | 1 | `0x06` ACK, `0x15` NAK, `0x55` BUSY, `0xEE` ERROR |
| `CHANNEL` | 1 | echo |
| `SEQ/OP` | 1 | echo |
| `LENGTH` | 2 | payload bytes, `0..1024` |
| `PAYLOAD` | M | trace data, flash status, ... |
| `CRC8` | 1 | |

Throughput at 10 MHz: TX 2.5 MB/s, RX 5 MB/s. The T20 SPI-flash write is slower than the bus, so flash streaming is chunked with one request/ACK per chunk (flow control by the response).

### 4.3 T120 hardware
`t120_sbus_tx.sv` (serialiser + CRC), `t120_sbus_rx.sv` (hunt `A5`, CRC check, RAM write), `t120_sbus_xact.sv` (command/ACK FSM with microsecond timeout), 1 KB TX buffer, 1 KB RX buffer. A response while the RX buffer is still occupied is dropped (`rx_ovf`), CRC errors set `crc_err`, a missing response sets `timeout` and may auto-pulse `T20_CRESET_N` (`auto_creset`).

## 6. T20 Reset (`T20_CRESET_N`)

The patch wire from the T120 to T20 `CRESET_N` is the T120 pin `T120_LED1` (LED1 is no longer a heartbeat). `t120_creset_controller.sv`: after T120 configuration the line is released (high). Software or the S-bus watchdog can pulse it low for a programmable time (default 12 ms, T20 needs >= 10 ms) and release; this forces the T20 back to its Golden Image.
